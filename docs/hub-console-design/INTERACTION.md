# homer hub 控制台 · 交互设计说明

> 设计目标（用户一句话验收）：**打开就知道发生了什么、下一步点什么**。
> 配套原型：`prototype.html`（浏览器直接打开，右上角场景切换器可走完所有场景）。

---

## 0. 诊断：现在的页面为什么"乱的一匹"

| 现页面问题 | 后果 |
|---|---|
| 7 个同级 section 平铺（状态卡/适配器卡/差异/操作/多机……） | 没有视觉层级，不知道先看哪 |
| 操作按钮（推送/拉取）与状态信息平级，放在差异框之后 | 用户要滚动寻找"下一步"，甚至找不到 |
| 3 张汇总卡 + N 张适配器卡 + 分类行，同一信息重复三遍 | 数字在，但"整体好不好"要心算 |
| 未初始化、未登录、加载失败共用"顶部报错卡"模式 | 非常态和常态抢同一个注意力通道 |
| 接入命令无处展示（`/api/auth/join` 已实现但 UI 没入口） | 用户故事 3 直接缺失 |

**根因：页面按"数据有什么"组织，而不是按"用户来干什么"组织。**

## 1. 信息架构

### 1.1 单一纵向流，区块按用户视线顺序排列

```
┌──────────────────────────────────────────────┐
│ header: homer · v1.x · [接入命令] [刷新] [退出] │  ← 全程可见，细条
├──────────────────────────────────────────────┤
│ ① 状态横幅 HERO                              │
│   ● 一切同步          （大字结论 + 强调色圆点） │
│   或 ● 有漂移：↑2 ↓1 · [处理漂移]（内嵌下一步）│
│   或 ● 有冲突，需终端处理                      │
│   或 ⚠ 尚未初始化 → 终端跑 homer init         │
├──────────────────────────────────────────────┤
│ ② 适配器明细（折叠成一行一个，点开看分类）      │
│   pi        ↑2 ↓0 ⚡1      [查看差异]          │
│   └ 展开: settings ↑2 [diff] · agents ⚡1      │
├──────────────────────────────────────────────┤
│ ③ 机器                                       │
│   ● nj-mac    connect · 2 分钟前               │
│   ○ old-box   listen · 3 天前 · 离线           │
│   [+ 接入新机器]                               │
├──────────────────────────────────────────────┤
│ footer 细条: 10:32 已自动刷新 · 版本号         │
└──────────────────────────────────────────────┘
```

### 1.2 每个区块的存在理由（防自嗨清单）

| 区块 | 用户什么时候需要它 | 不需要时的处理 |
|---|---|---|
| ① 状态横幅 | **每次打开页面的第一眼**（用户故事 1） | 永远存在；干净时它自己变小变安静 |
| ② 适配器明细 | 有漂移/冲突，想知道"哪里漂了"（故事 2） | 干净时整个区块收起为一行"全部干净"，不展开 |
| 差异抽屉 | 决定推还是拉之前看一眼（故事 2） | 默认收起，按需加载；干净时不显示入口 |
| ③ 机器 | 接新机器 / 看谁离线了（故事 3、4） | 永远存在（哪怕空的，空态即引导） |
| header 接入命令 | 故事 3 | 常驻但低调（细按钮），点开即复制 |
| footer 刷新时间 | "这数据新不新鲜？" | 一行小字，无存在感 |

**关键取舍：操作按钮（推送/拉取）不是独立区块。** 它们是横幅的附属物——有漂移时出现在横幅里，没漂移时根本不存在。"什么时候能点推送"这个问题的答案由系统状态给出，而不是让用户自己判断。

### 1.3 层级原则

- 一页只有**一个强调色元素**（当前最重要的事）。干净时强调色只出现在横幅的"●"上；漂移时出现在"处理漂移"按钮上；冲突时出现在警告横幅上。
- 黑白灰承担一切结构性信息；颜色只编码语义：`同步中=强调色`、`冲突/错误=红色`、`离线/禁用=灰`。
- 无卡片阴影、无圆角堆砌、无渐变。分隔靠留白和 1px 灰线。

## 2. 设计 Token

```
颜色
  --ink:      #1a1a1a   正文
  --ink-dim:  #6b6b6b   次要文字
  --line:     #e2e2e2   分隔线（1px）
  --bg:       #ffffff
  --bg-sink:  #f6f6f6   代码块/差异框/表格斑马纹
  --accent:   #0a7d4f   强调色：同步中/主要按钮（深绿，白字对比度 4.9:1 过 AA）
  --danger:   #b3261e   冲突/错误/离线之外的破坏性提示（白字对比度 5.9:1）

字阶（system-ui 栈）
  --fs-hero:  1.5rem    横幅结论（"有漂移"）
  --fs-body:  0.9375rem 正文/表格
  --fs-small: 0.8125rem 辅助说明/时间戳

圆角：统一 4px（仅按钮/输入框/抽屉容器）

断点（桌面优先 + 移动适配）
  ≥640px：适配器行横向排列（名称 | 计数 | 按钮）
  <640px：适配器行变两行（名称+计数 / 按钮右对齐），header 按钮缩为图标+短文案
```

## 3. 场景流程

### 3.1 首启（`/api/auth/status.configured=false`）

```
打开页面
  → GET /api/auth/status
  → configured=false：全屏只显示「设置管理员密码」表单
      - setupCodeRequired=true（公网对端）：初始化码输入框首屏即显示
        （现有实现已修正此行为，保留）
      - 密码两次输入不一致 → 内联红字，不发请求
      - POST /api/auth/setup 成功 → 直接进入主界面（已登录态）
      - 失败（403 setup-code-required / 422 弱密码）→ 内联错误，不清空已填内容
```

设计要点：首启/登录是**全屏独占态**，不是主界面上的一个 section。用户此时没有任何状态可看，不给他看残缺的仪表盘。

### 3.2 登录 / 登出 / 改密码

```
登录：全屏独占表单（同首启的结构）。
  - 401（任何 API 返回）→ 静默清空页面状态 → 显示登录表单 + "会话已过期，请重新登录"提示条
  - 登录失败 → 内联红字，密码框保留焦点
登出：header 右端文字按钮，点击即 POST /api/auth/logout → 回到登录表单（无确认弹窗，成本为零的操作不打断）
改密码：产品决策——不做 UI，在登录页放一行灰色小字：
        "忘记密码？删除 hub 上的 ~/.homer/hub/password 文件后重启服务即可重设"
        （用户是本人+懂 ssh，一行指引比一套改密流程更省）
```

### 3.3 日常巡检（干净态）— 最高频场景

```
打开页面（已登录、已 init、无漂移）
  → 横幅：● 一切同步        ← 强调色圆点 + 两个字级别的结论
        4 个适配器 · 2 台机器在线 · 刚刚刷新
  → 适配器区块：收起为一行 "pi / herdr / opencode 全部干净 ▸"
  → 机器区块：● 在线列表
  → 没有按钮需要点。3 秒看完，关掉页面。✅ 设计成功
```

干净态的核心是**让页面"无聊"**：没有按钮、没有红色、没有待办。无聊=安心。

### 3.4 处理漂移 — 决策路径最重的场景

```
① 横幅：● 有漂移   本机 2 项改动可推送 · 仓库 1 项可拉取
        [处理漂移 →]  ← 页面唯一强调色按钮，点击平滑滚动到 ②

② 适配器明细（自动展开有漂移的 adapter）：
   pi   ↑2 ↓1 ⚡0
     ├ settings  ↑2        [查看差异]
     └ agents    ↓1        [查看差异]
   herdr 全部干净（灰字，不展开）

③ 点 [查看差异] → 行内展开抽屉，GET /api/diff?adapter=pi&category=settings
   → 渲染统一 diff（等宽字体，+行绿/-行红——diff 着色是语义编码，不是装饰）
   → 抽屉底部两个按钮：[推送本机改动] [拉取仓库改动]

④ 点推送 → 确认对话框：
   「推送 2 项改动到仓库？」受影响文件会先备份。
   [取消] [确认推送]
   → POST /api/push?confirm=true
   → 成功：横幅刷新为"一切同步"，toast "推送成功，处理 2 个文件"
   → secrets 拒绝（422 secrets-rejected）：错误横幅置顶
     "检测到疑似密钥，已拒绝推送：settings.json:42" + [查看详情展开]
   → 409 aborted：内联提示"操作已中止：{errors}"

⑤ 冲突（⚡>0）：
   → 横幅直接变红系：⚡ 1 个冲突需要终端处理
     运行 homer merge 解决后回到这里刷新
   → 推送/拉取按钮**不显示**（按现状后端会 409，与其让用户撞墙不如先收走按钮）
   → 冲突行仍提供 [查看差异]，帮用户判断是什么冲突
```

设计要点：
- **"先看到漂成什么样，再决定推/拉"** —— diff 抽屉和推/拉按钮物理上绑定在一起，不在页面另一头。
- 推/拉的确认对话框复用现有 `<dialog>` 模式，但摘要文案从"预计处理 N 项状态变更"改为明确的方向句（"推送 N 项改动到仓库，本机为准"/"拉取 N 项改动到本机，覆盖本地文件前先备份"）。

### 3.5 接新机器

```
入口 A（主路径）：③ 机器区块底部 [+ 接入新机器]
入口 B（header）：[接入命令] 细按钮
  → 对话框：一行等宽命令（GET /api/auth/join）+ [复制] 按钮
  → 复制成功 → 按钮文案变"已复制 ✓" 2 秒
  → 对话框内一行说明："在新机器终端运行这条命令，接入后出现在下方列表。"
  → 关闭对话框，列表不自动刷新；30s 轮询会带出新机器（或由手动刷新触发）
```

复制用 `navigator.clipboard`，降级方案：选中文本框 + "按 Ctrl+C"（http 环境 clipboard API 不可用，自托管很可能就是 http 内网）。

### 3.6 看谁离线

```
机器行：● 在线（lastSeen < 阈值） / ○ 离线（stale=true，整行降灰）
离线行附加一句灰色小字："3 天前最后心跳 · 离线期间不产生同步"
不做删除/踢出按钮（API 没有，也不该让用户在 UI 里管理 registry——终端事终端办）
```

## 4. 空状态设计

| 状态 | 呈现 | 文案要点 |
|---|---|---|
| 未 init（409 not-initialized） | 横幅变指引块：⚠ 尚未初始化 + 等宽命令 `homer init` + "在终端运行后回到这里刷新" | 不说"错误"，说"还差一步" |
| 无 agent | 机器区块空态：一行灰字 "还没有机器接入" + [+ 接入新机器] 按钮 | 空态即引导，不显示空表格 |
| 无漂移 | 横幅"一切同步"；适配器区块收起为一行 | 干净态的奖励是"没有东西要看" |
| 某 adapter 无 categories | 行内显示"无分类数据"（灰） | 不渲染空列表 |
| diff 为空（empty=true） | 抽屉内："无漂移" | 理论上用户不会在干净时点开，但兜底 |
| 多机视图未启用（501 agents-disabled） | 机器区块显示一行灰字"多机未启用"，**隐藏**接入命令入口 | 区分"没有机器"和"功能没开" |

## 5. 错误呈现规则

**原则：错误出现在"离它产生的原因最近的地方"。只有阻断当前唯一任务的错误才打断。**

| 级别 | 触发 | 呈现 |
|---|---|---|
| **打断（modal/全屏）** | 401 会话过期；推送/拉取前的确认对话 | 确认对话框（可预期、用户主动触发）；401 直接切登录页+提示条 |
| **页级横幅（置顶，不遮罩）** | secrets-rejected（422）；conflicts（409）；状态接口整体失败 | 横幅下方插一条红边提示条，含下一步指引，可手动关闭 |
| **内联（区块内）** | diff 加载失败、agents 加载失败、登录/首启表单校验失败 | 该区块内红字 + [重试]；其余区块不受影响 |
| **静默降级** | 自动轮询失败一次、版本号拿不到 | footer 时间戳变灰 "10:32 刷新失败，下次自动重试"；不弹任何东西 |

- 所有错误文案 = "发生了什么 + 下一步怎么办"，禁止裸贴后端 error.message 而不给动作。
- `not-initialized` 永远走"指引块"而不是"错误条"——它不是故障，是流程的一步。
- 409 aborted / 422 的 errors 数组逐条列出（密钥检测结果要让用户能定位到文件:行）。

## 7. 可访问性

- 全部交互元素用原生 `<button>/<input>/<select>/<dialog>`，键盘 Tab 路径 = 视觉顺序（banner 按钮 → 适配器行按钮 → 机器区按钮 → header）。
- diff 抽屉用 `aria-expanded` + `aria-controls`；对话框用原生 `<dialog>`（自动焦点圈禁+Esc 关闭）。
- 状态圆点不单独承担语义：● 永远伴随文字（"在线"/"一切同步"），色盲用户不靠颜色也能读。
- 强调色/危险色文字对比度均 ≥4.5:1（见 token 注释）。
- 自动刷新不打断阅读：轮询只更新数据，不在用户展开抽屉时重置展开态（展开状态存于 JS 内存，按 adapter+category 做 key）。
- `prefers-reduced-motion` 下关闭平滑滚动和过渡。

## 8. 响应式

- <640px：header 折行（标题一行、按钮一行）；适配器行的计数与按钮分两行；对话框宽度 100%-32px；diff 抽屉内等宽字体缩到 12px 并允许横向滚动（diff 不可换行，换行就看不懂了）。
- 横幅在移动端仍然只占首屏 ≤40%：结论一行、数字一行、按钮一行。

## 9. 实现边界说明（给 worker 的交接）

- 本设计不改任何 API；全部数据来自任务书列出的既有端点。
- 需要从既有代码迁移的交互逻辑：401 路由、setup-code 首屏显示、confirm 对话框的 dialog/confirm() 双实现、secrets-rejected 文案分支——这些在现有 index.html 里已写对，重排时**保留逻辑、替换结构**。
- footer 自动刷新建议 30s 轮询 `/api/status` + `/api/agents`（均为 GET，无副作用）；页面 `visibilitychange` 回到前台时立即刷一次。
- `changedFiles` 等推送报告字段名沿用现有 `reportMessage()` 的判断逻辑。
