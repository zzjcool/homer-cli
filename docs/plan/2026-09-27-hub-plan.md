# Homer Hub 演进实施计划（P1/P2/P3 · TDD）

**日期**: 2026-09-27 · **状态**: ✅ 已交付（P1/P2/P3 完成，三路对抗 review 闭环，容器 E2E 通过） · **上游文档**: docs/plan/2026-09-27-hub.md, DESIGN.md §6 M6

## 0. 目标与不做的事

**目标**：在不破坏零运行时依赖原则（仅 age + survey 两个既有依赖，HTTP 全部用标准库 `net/http`）的前提下，分三个可独立交付的阶段落地 hub 形态：P1 `homer serve` 本地 HTTP API + 内嵌单文件 Web UI；P2 `homer agent` 双模式 + hub 注册表；P3 hub 多机远程视图。同步语义 100% 复用 `internal/cli/commands` → `engine/sync/gitx`，**hub 不新增任何存储**。

**Non-goals（本计划明确不做）**：
- 不做网页 init 向导（P1 只读命令 + push/pull 按钮；向导保持 CLI 交互式，网页端对未初始化状态只显示引导文案）
- 不做 WebSocket（见 §2.3 评估，选 HTTP 长轮询）
- 不做多用户/多租户（单用户单 token）
- 不做 TLS 终结（公网部署走用户自己的反代；hub 只提供 token 鉴权）
- 不做 homer.json 的网页编辑（GET /api/config 只读）
- 不做 merge 网页交互（冲突仍走 CLI `homer merge`；网页显示冲突计数与提示）
- 不引入任何新 Go 依赖、不做前端构建链（单文件 vanilla JS）

## 1. 总体架构与阶段划分

```
浏览器 ──HTTP──▶ homer serve (internal/web)  ──库调用──▶ internal/cli/commands ──▶ engine/sync/gitx/core
                    │                                               
P2:  agent(listen) ◀──hub 直连(Bearer)── Dispatcher ──┐
     agent(connect) ──POST 长轮询──▶ /agent/v1/* ◀── Registry (internal/hub)
P3:  /api/agents/{id}/status|diff|push|pull  ──▶ Dispatcher(直连或投递)
```

- **P1**：`internal/web` 完整可用（local 路由 + 鉴权 + 静态 UI + AgentsSource 接口位），`homer serve` 注册进 CLI。独立可交付。
- **P2**：`internal/hub`（Registry + /agent/v1/* HTTP 端点 + Dispatcher）+ `internal/agentd`（listen/connect 双模式）+ `homer agent` 注册进 CLI。
- **P3**：hub web 的 agent 代理路由接通 Dispatcher（路由在 P1 已冻结，P2 接实现），UI agent 区块真数据。

## 2. 冻结接口（所有 worker 不得自行发明）

### 2.1 鉴权（决策：统一单 token）

**建议与结论：单一 hub token**，环境变量 `HOMER_HUB_TOKEN`（CLI `--token` 可覆盖）。理由：单用户场景下 hub token 与 agent token 分离只有运维成本没有安全收益（同一个人持有两者）；agent 个体身份用 `agentId` 表达（自报 hostname + 短随机后缀），不需要独立凭证。浏览器与 agent 用同一个 Bearer token。

规则（冻结）：
1. Token 为空：仅当 serve 绑定回环地址（`127.0.0.1`/`localhost`/`[::1]`）时允许启动（P1 默认形态，本机即信任）。
2. Token 非空：所有 `/api/*`（除 `/api/health`）与 `/agent/*` 必须 `Authorization: Bearer <token>`；错误 → 401。
3. `GET /` 与静态资源、`GET /api/health` 永远放行（容器健康检查与首屏需要）。
4. 风险承认：token 泄漏即全权（push/pull/读配置）。缓解：默认回环、非回环强制 token、文档建议公网加反代 TLS。未来多用户再演进 per-agent token（Registry 结构已预留 `Version` 字段位）。

### 2.2 `internal/web` HTTP API 面（P1 冻结，P2/P3 只加不改）

**路由表**：

| 方法+路径 | 鉴权 | 语义 | 成功响应 | 失败响应 |
|---|---|---|---|---|
| `GET /api/health` | 免 | 存活+版本 | 200 `{"ok":true,"status":"healthy","version":"...","homerHome":"..."}` | 仅 500 internal |
| `GET /api/status` | Bearer | 本机 StatusReport | 200 `{"ok":true,"report":{StatusReport}}` | 409 not-initialized / invalid-config |
| `GET /api/diff?adapter=&category=` | Bearer | 本机 diff 文本 | 200 `{"ok":true,"empty":bool,"text":"..."}` | 409 not-initialized 等 |
| `POST /api/push` | Bearer | 推送（幂等门：confirm） | 200 PushReport 本体 | 见下方状态映射 |
| `POST /api/push?confirm=true` | Bearer | 确认后执行 | 200/422 PushReport 本体 | 同上 |
| `POST /api/pull` / `?confirm=true` | Bearer | 拉取 | 200/422 PullReport 本体 | 同上 |
| `GET /api/config` | Bearer | 读 homer.json | 200 `{"ok":true,"config":{原文键序}}` | 409 not-initialized / invalid-config |
| `GET /api/agents` | Bearer | agent 列表（P1 恒空） | 200 `{"ok":true,"agents":[]}` | — |
| `POST /api/agents/{id}/status` | Bearer | 远程采集（P2 起） | 200 `{"ok":true,"report":{StatusReport}}` | 404/502/504/501 |
| `POST /api/agents/{id}/diff?adapter=&category=` | Bearer | 远程 diff | 200 `{"ok":true,"text":"..."}` | 同上 |
| `POST /api/agents/{id}/push?confirm=` | Bearer | 远程 push | Report 本体（同 /api/push 映射） | 同上 |
| `POST /api/agents/{id}/pull?confirm=` | Bearer | 远程 pull | Report 本体 | 同上 |
| `GET /` | 免 | Web UI 单页 | 200 text/html | — |
| `GET /agent/v1/info`（仅 listen agent 实例） | Bearer | agent 自述 | 200 `{"ok":true,"identity":{AgentIdentity}}` | 401 |
| `/agent/v1/register|poll|report`（仅 hub 实例挂载） | Bearer | 见 §2.4 | 见 §2.4 | 见 §2.4 |

**写操作确认语义（冻结：`?confirm=true` 两段式）**：
- `POST /api/push`（无 confirm）→ web 层调 `commands.RunPush(PushOptions{Yes:false}, nil)`。server 进程 `isTTY()==false`，`promptConfirm` 走 fallback=false → 返回 aborted 报告（内含 changedFiles 预览）→ **HTTP 409 + PushReport 本体**（`status:"aborted"`）。
- `POST /api/push?confirm=true` → `RunPush(PushOptions{Yes:true}, nil)` 真执行。
- pull 同理（409 aborted；UI 的确认弹窗内容来自已加载的 status/diff，不重复造预览接口）。
- **HTTP 状态映射（push/pull/agents push/pull 通用）**：`report.OK==true` → **200**（Report 本体）；`!OK && status=="aborted"` → **409**（Report 本体，UI 据此弹确认框）；`!OK && 其他`（secrets-rejected/remote-ahead/conflicts/error 等）→ **422**（Report 本体）。

**统一错误 envelope（传输层与意外错误，两种 body 形态之二）**：
```json
{"error": {"code": "<machine-code>", "message": "<中文>", "details": ["..."]}}
```
code → HTTP 映射：`unauthorized`→401、`not-found`→404、`method-not-allowed`→405、`not-initialized`/`invalid-config`→409、`agents-disabled`→501、`agent-not-found`→404、`agent-unreachable`→502、`agent-timeout`→504、`bad-request`→400、`internal`→500。
**规则总结：2xx 与 409（写确认）返回资源本体（Report/带 ok 的对象）；其余非 2xx 一律 error envelope。** `/api/*` 全部 `Content-Type: application/json; charset=utf-8`。

**Go 类型（完整冻结，文件 `internal/web/server.go`）**：
```go
package web

type AgentIdentity struct {
    AgentID  string `json:"agentId"`
    Hostname string `json:"hostname"`
    Version  string `json:"version,omitempty"`
}

type AgentInfo struct { // hub 的 Dispatcher 适配成此形状
    AgentID  string    `json:"agentId"`
    Hostname string    `json:"hostname"`
    Mode     string    `json:"mode"`            // "listen" | "connect"
    Addr     string    `json:"addr,omitempty"`  // listen 模式直连地址，如 "http://agent-a:7761"
    LastSeen time.Time `json:"lastSeen"`
    Version  string    `json:"version,omitempty"`
}

type DiffParams struct {
    Adapter  string `json:"adapter,omitempty"`
    Category string `json:"category,omitempty"`
}

// AgentError 是 AgentsSource 实现方向 web 报告结构化失败的标准方式。
type AgentError struct {
    Code   string // "agent-not-found"|"agent-unreachable"|"agent-timeout"
    Status int    // 404|502|504
    Err    error
}
func (e *AgentError) Error() string // "agent: " + Code + ": " + Err.Error()
func (e *AgentError) Unwrap() error

// AgentsSource 由 internal/hub 的 Dispatcher 实现；P1 serve 传 nil。
type AgentsSource interface {
    ListAgents() []AgentInfo
    AgentStatus(ctx context.Context, agentID string) (json.RawMessage, error) // 返回 StatusReport 的 JSON
    AgentDiff(ctx context.Context, agentID string, params DiffParams) (string, error)
    AgentPush(ctx context.Context, agentID string, confirm bool) (json.RawMessage, error) // PushReport JSON
    AgentPull(ctx context.Context, agentID string, confirm bool) (json.RawMessage, error) // PullReport JSON
}

type ServeOptions struct {
    Addr         string         // 必填；listen agent 也用（如 "0.0.0.0:7761"）
    HomerHome    string         // 传给 commands 层的 --home（对应 StatusOptions.HomerHome 等）
    Token        string         // 空 ⇒ Addr 必须是回环
    Identity     *AgentIdentity // listen agent 注入；hub/单机 serve 为 nil
    Agents       AgentsSource   // nil ⇒ /api/agents 返回 []，agents 子路由 501 agents-disabled
    AgentEndpoint http.Handler  // 可选；非 nil 时整体挂载到 /agent/v1/（hub 侧由 internal/hub 提供）
}

func NewServer(opts ServeOptions) (*Server, error)
func (s *Server) Handler() http.Handler          // 纯 http.Handler，供 agentd/测试复用
func (s *Server) ListenAndServe() error          // ReadHeaderTimeout 10s / WriteTimeout 90s（> PollWait 25s）
```
**并发约束（冻结）**：`POST /api/push`、`POST /api/pull`（含 agents 子路由透传前）共享 web 包内**一把进程级互斥锁**（`sync.Mutex`），写操作全串行化，防止并发 git 工作区竞争。锁忙时直接排队（不返回 busy），因为命令本身秒级完成。
**实现约束**：status/diff/push/pull 直接调 `commands.RunStatus/RunDiff/RunPush/RunPull`（签名见仓库现状，已满足需要，零修改）；Report 序列化用 `encoding/json`（json tag 已齐全）；`/api/config` 用 `orderedjson.Parse` 保持键序。
**静态资源**：`internal/web/static/index.html`，`//go:embed` 进二进制；`GET /` 输出它。

### 2.3 connect 模式协议（冻结：HTTP 长轮询，否决 WebSocket）

**评估**：WebSocket 需在零依赖前提下自实现 RFC6455（握手 Sec-WebSocket-Accept SHA-1、帧掩码解析、ping/pong、close 握手，约 300 行 + 大量边界测试）；长轮询服务端只需 `select {ctx.Done / timer / channel}`，对 NAT 纯出站友好，agent 任务频率是人工触发的秒级延迟容忍场景。**结论：HTTP 长轮询。** 代价：空闲 agent 每 25s 一个空 POST（个位数 agent 可忽略）。

协议（hub 侧挂载在 `/agent/v1/`，全部 Bearer token）：
```
POST /agent/v1/register
  req:  {"agentId":"agent-a","hostname":"box-a","mode":"listen"|"connect",
        "addr":"http://agent-a:7761",      // 仅 listen 模式必填
        "version":"v1.3.0"}
  res:  200 {"ok":true,"heartbeatSeconds":60}
  err:  400 bad-request（mode=listen 无 addr、mode 非法）

POST /agent/v1/poll          ← 每次 poll 即心跳
  req:  {"agentId":"agent-a","waitSeconds":25}
  res:  200 {"ok":true,"task":{"taskId":"t-000001","kind":"status","options":{"adapter":"","category":"","confirm":false},"createdAt":"RFC3339"}}
        或 200 {"ok":true,"task":null}          // 挂到 waitSeconds 到期
  err:  404 agent-not-found（未注册先 poll）

POST /agent/v1/report
  req:  {"agentId":"agent-a","taskId":"t-000001","ok":true,
        "report":{ ...按 kind：StatusReport / {"text":"..."} / PushReport / PullReport... }}
  res:  200 {"ok":true}
  err:  404 task-not-found（已回报/未知/过期）
```
task.kind ∈ `status | diff | push | pull`；options 即 `web.DiffParams` + `confirm bool`。任务过期：创建后 120s 未回报即作废（report → 404）。

### 2.4 `internal/hub` Registry（冻结签名，文件 `registry.go` / `dispatcher.go`）

```go
package hub

type AgentMode string
const (
    AgentModeListen  AgentMode = "listen"
    AgentModeConnect AgentMode = "connect"
)

type TaskKind string
const (
    TaskKindStatus TaskKind = "status"
    TaskKindDiff   TaskKind = "diff"
    TaskKindPush   TaskKind = "push"
    TaskKindPull   TaskKind = "pull"
)

type Task struct {
    TaskID    string          `json:"taskId"`
    Kind      TaskKind        `json:"kind"`
    Options   TaskOptions    `json:"options"`
    CreatedAt time.Time       `json:"createdAt"`
}
type TaskOptions struct {
    Adapter  string `json:"adapter,omitempty"`
    Category string `json:"category,omitempty"`
    Confirm  bool   `json:"confirm,omitempty"`
}
type TaskResult struct {
    TaskID  string          `json:"taskId"`
    AgentID string          `json:"agentId"`
    OK      bool            `json:"ok"`
    Kind    TaskKind        `json:"kind"`
    Report  json.RawMessage `json:"report,omitempty"`
    Error   string          `json:"error,omitempty"`
}

const (
    TaskQueueCapacity = 8              // 每 agent 待执行队列上限
    TaskTTL           = 120 * time.Second
    AgentStaleAfter   = 90 * time.Second // LastSeen 超过即标记 stale（不删除，List 标 ok:false）
)

func NewRegistry() *Registry
func (r *Registry) Register(info AgentInfo) error        // upsert；mode=listen 必须有 Addr；agentId 非空
func (r *Registry) Touch(agentID string)                // 心跳（poll/register 时调用）
func (r *Registry) Get(agentID string) (AgentInfo, bool)
func (r *Registry) List() []AgentInfo                    // 按 AgentID 排序的深拷贝；附 stale 计算
func (r *Registry) Enqueue(agentID string, task Task) error // 未知 agent / 队列满 → error
func (r *Registry) Poll(agentID string, wait time.Duration, ctx context.Context) (Task, bool)
        // 无任务阻塞至 wait 到期或任务到来或 ctx.Done；任务只投递一次
func (r *Registry) Submit(result TaskResult) error       // 未知/已回报/过期 taskID → error
func (r *Registry) Wait(ctx context.Context, taskID string) (TaskResult, error)
        // 阻塞至 Submit 或 ctx.Done / TaskTTL 过期

// Dispatcher 实现 web.AgentsSource（listen 直连 / connect 投递等待）
type Dispatcher struct {
    Registry *Registry
    Client   *http.Client // 超时默认 60s
    Token    string
}
func NewDispatcher(reg *Registry, token string) *Dispatcher
// AgentStatus/AgentDiff/AgentPush/AgentPull/ListAgents 实现 web.AgentsSource；
// listen → 直连 info.Addr + Bearer 调 agent 的 /api/*；connect → Enqueue+Wait；
// 失败统一返回 *web.AgentError（not-found→404、连接失败→unreachable→502、超时→504）。
```
**并发安全要求（冻结）**：Registry 所有方法内部一把 `sync.Mutex`；长轮询等待用 per-task `chan struct{}` + `sync.Cond` 或 select 通道（不许忙等）；返回值一律拷贝；必须以 `go test -race` 通过为验收。

### 2.6 CLI 面（冻结，归主 agent 修改 `internal/cli/`）

```
homer serve [--addr 127.0.0.1:7760] [--home <dir>] [--token <t>]     # 前台运行，启动打印 URL 与鉴权提示
homer agent (--listen <addr> | --connect <url>) [--hub <url>] [--advertise <url>]
            [--token <t>] [--home <dir>] [--id <agentId>]
```
- `--token` 缺省读 `HOMER_HUB_TOKEN`；serve 绑非回环且无 token → 退出 1 + 中文错误。
- `parseOptions` 的 `CommandOptions` 新增字段：`Addr/Listen/Connect/Hub/Advertise/Token/ID`；`validateCommandOptions` 白名单：serve 允许 `home/token/addr`，agent 允许 `home/token/listen/connect/hub/advertise/id`，且 listen/connect 恰有一个、listen+connect 同时给 → 用法错误。
- `COMMANDS`/`USAGE`/`commandUsage` 同步新增两行（中文）。
- serve/agent 分发进 `runWithIO` 的 switch（serve/agent 阻塞运行，需 ctx 捕获 SIGINT/SIGTERM 优雅退出，参考 `ExecutePair` 的 `signal.NotifyContext` 模式）。

### 2.7 Web UI（`internal/web/static/index.html`，单文件 vanilla JS，全中文 i18n）

区块（P1 全部交付，agent 区块 P1 空态/P3 真数据）：
1. **顶栏**：homer 标识 + 版本（/api/health）+ 「刷新」按钮 + token 输入框（401 时出现，值存 sessionStorage，之后所有 fetch 加 Bearer）
2. **状态卡片区**（`#status-cards`）：总览卡（↑/↓/⚡ 计数）+ 每 adapter 卡片（`/api/status` → report.adapters；显示分类明细、disabled、warnings/errors 折叠列表）
3. **Diff 视图**（`#diff-view`）：adapter/category 过滤下拉 + `<pre>` 渲染 `/api/diff` 的 text；无漂移显示「无漂移」
4. **操作区**（`#actions`）：「推送」/「拉取」按钮 → 点击先 GET 最新 status/diff 弹**确认对话框**（列出将变更文件数与提示「受影响文件会先备份」）→ 对话框内「确认推送/确认拉取」第二次点击才发 `?confirm=true`；响应 Report 渲染结果（成功/密钥拒绝/冲突各自中文文案，冲突时提示「请在终端运行 homer merge」）
5. **Agent 列表**（`#agents`）：表格（agentId/主机名/模式/最近心跳/状态点）+ 每行「查看状态/查看差异/拉取」按钮（P3 才可用；P1 显示「未启用多机视图」空态）
6. **未初始化空态**（`#not-initialized`）：`/api/status` 返回 409 not-initialized 时显示「请先在终端运行 homer init 完成初始化，再回到本页」
实现约束：零构建零 npm；`fetch` + `URLSearchParams`；ES2020 即可；所有文案中文写死（i18n = 中文文案本身，不做多语言框架）。

## 4. 风险清单与回退

| # | 风险 | 概率/影响 | 缓解与回退 |
|---|---|---|---|
| R1 | **非 TTY 确认语义被破坏**：409 语义依赖 `RunPush/RunPull` 在无 `--yes` 且非 TTY 时走 fallback=aborted。已核实 `promptConfirm` 先查 `isTTY()`，非 TTY 不触 survey，直接 fallback。但若未来有人给 server 进程接 TTY 判定，语义漂移 | 低/高 | 测试 `TestPushRequiresConfirm` 锁死该行为；计划注明该依赖为契约 |
| R2 | **并发写竞争**：多请求同时 push/pull 操作同一 git 工作区 | 中/高 | web 写路由进程级互斥（§2.2 冻结）；回退：若互斥引入问题，降级为「写路由忙时 409 busy + Retry-After」 |
| R3 | **长轮询 goroutine/连接泄漏**：Poll 挂起泄漏、WriteTimeout 杀长连接 | 中/中 | Poll 只 select ctx.Done/wait timer/task chan；Server WriteTimeout 90s > PollWait 25s；回退：PollWait 降到 5s 短轮询（协议不变） |
| R4 | **容器内 git 缺身份/缺 git 二进制**：commit 失败、distroless 无 git | 高/中 | 镜像 alpine+git + GIT_CONFIG_GLOBAL 预设；e2e 脚本首步断言 `git --version` |
| R5 | **token 泄漏即全权**（push/pull/读配置） | 中/高 | 默认回环；非回环强制 token；文档建议公网走反代 TLS；compose 只用 test token |
| R6 | **commands 层签名漂移**（后续 homer 版本改 RunPush 签名）| 低/中 | 本计划把所用签名列为冻结契约；reviewer ① 检查 |
| R7 | **UI 无构建链导致回归不可见** | 中/低 | `TestStaticIndexServed` 用区块 id 字符串断言防呆 + 冒烟脚本 grep |

**回滚点**：T1 末 commit（P1 web+registry 可独立合并）、T2 末 commit（P2 完整）、T3 末 tag。任一阶段失败回滚到上一检查点，P1 独立可交付不受 P2/P3 失败影响。

## 摘要（给主 agent）

- **决策**：connect 协议选 HTTP 长轮询（否决零依赖 WebSocket 自实现）；鉴权统一单 token `HOMER_HUB_TOKEN`（浏览器与 agent 共用 Bearer，回环免 token、非回环强制）；写操作确认用 `?confirm=true` 两段式（无 confirm → `RunPush/RunPull(Yes:false)` 在非 TTY server 进程天然 aborted → HTTP 409 + Report 本体，**commands 层零修改**）；push/pull 的 HTTP 映射 200/409(aborted)/422(其他 !ok)，其余错误统一 error envelope。
- **冻结面**：`internal/web`（ServeOptions/Server/AgentsSource/AgentError/AgentIdentity + 完整路由表与 JSON schema）、`internal/hub`（Registry 全方法签名 + Task/TaskResult + 并发要求：单锁、任务单次投递、TTL 120s、队列 8、`-race` 验收）、`internal/agentd`（Config/Mode/DefaultAgentID/Executor/Daemon）、CLI flags（serve/agent）。依赖方向：hub→web、agentd→web、web→commands，无环。
- **并行结构**：T1 双 worker 并行（web P1 ‖ hub Registry，互不依赖）→ T2 双 worker（dispatcher+agentd ‖ web agent 路由+UI 真数据）→ T3 主 agent 串行（CLI 注册 + e2e 容器 compose：origin git daemon + hub + agent-a listen + agent-b connect）→ T4 三路对抗 review。回滚点在每阶段末 commit。
- **P1 不做网页 init 向导**（CLI only，UI 显示 not-initialized 引导）；**init/config 全只读**；冲突仍走 CLI merge。
- 最大的三个坑已在上文 R1–R3 锁测试：非 TTY aborted 语义、写互斥、长轮询超时。
