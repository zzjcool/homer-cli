# Hub 演进：homer serve + agent 拓扑（自治开发会话）

**日期**: 2026-09-27
**状态**: 执行中（用户授权全自治，明天验收）
**授权范围**: 用户要求 TDD、充分利用子 agent、E2E + 容器验证、前端/HTTP 每环节验证、不可决定问 advisor、不中途打扰用户

## 需求（用户原话摘要）

1. 中心节点（hub）部署在公网/可达处，机器多、不可能每台都登录
2. 两种连接方向：
   - **正向采集（中心→机器）**: 机器可达 → 中心直连采集
   - **反向上报（机器→中心）**: 机器在 NAT 后 → 机器上填中心地址主动拨出
3. 网页交互（SPA）
4. 完整 E2E + 单元测试 + 容器环境完整跑起来验证（前端/HTTP/每一环节）

## 架构决策（已定）

- **P1 `homer serve`**: 本地 HTTP server + 内嵌静态 Web UI（单机网页版），复用 commands 层
- **P2 `homer agent`**: 两种模式（--listen 中心直连 / --connect 中心拨出），hub 维护 agent 注册表，中心对可达机器远程执行状态采集
- **P3 hub 多机视图**: Web UI 上看每台机器的 status/diff，远程 pull/push
- 技术栈: Go 标准库 net/http（零新增依赖原则），Web UI 用单文件 HTML+vanilla JS（零构建、零 npm 依赖）
- hub 是 git remote 的代理，不是又一个存储；同步语义全部复用 engine/sync/gitx

## 文件归属规划（worker 拆分用）

- `internal/web/`（新包）: HTTP API + 静态 UI 服务 — worker A
- `internal/agentd/`（新包）: agent 守护进程（listen/connect 双模式）— worker B
- `internal/hub/`（新包）: hub 侧 agent 注册表 + 代理调用 — worker B 同包
- `cmd/homer/` 入口 + `internal/cli/` 命令注册: 主 agent 统一改（避免冲突）
- `docs/plan/` 讇ons plan: 主 agent
- DESIGN.md M5/M6 章节: 主 agent
- 容器 E2E: `e2e/` 目录, 主 agent 统一写（worker 只提供单元层）

## 里程碑验收标准

- P1: `homer serve` 起服，浏览器/`curl` 全命令链可用，容器内验证
- P2: docker compose 起 hub+agentA(公网模式)+agentB(NAT 模式)，hub 能列出/采集两台
- P3: 完整 E2E: agentA push → agentB pull，配置在容器间真实流转
- 最终: 对抗式 review（多角度）+ 全量测试绿
